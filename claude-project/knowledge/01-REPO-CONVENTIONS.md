# Repo conventions: Naxasware-Plugins (authoritative)

Repo: https://github.com/Naxasware/Naxasware-Plugins · default branch `main` · license **Apache-2.0** (root `LICENSE`) · marketplace name `naxasware-plugins` · owner/author: Naxasware (https://github.com/Naxasware).

## Layout

```
Naxasware-Plugins/
├── .claude-plugin/marketplace.json     GENERATED by scripts/sync_repo.py (Sync workflow). Never hand-edit.
├── README.md                           plugin table between <!-- PLUGINS:START/END --> is GENERATED.
├── plugins/<plugin-name>/              one self-contained plugin per folder
│   ├── .claude-plugin/plugin.json      required
│   ├── skills/<skill-name>/
│   │   ├── SKILL.md                    required
│   │   ├── references/*.md             optional, loaded on demand
│   │   └── scripts/*.py                optional, stdlib-only preferred
│   ├── examples/                       optional fixtures/sample outputs
│   ├── docs/                           optional
│   ├── README.md                       required
│   ├── CHANGELOG.md                    required in practice
│   └── ci-smoke.sh                     optional, executable; CI runs it
├── templates/plugin-template/          scaffold (outside plugins/, never validated)
├── scripts/                            validate_all_plugins.py, sync_repo.py, new_plugin.py, package_plugin.py
├── claude-project/                     this kit
├── docs/                               ADDING-A-PLUGIN, AUTOMATION, RELEASING
└── .github/                            workflows, templates, dependabot
```

**Your deliverable is only `plugins/<plugin-name>/`.** Everything else is generated or maintained by the repo owner.

## Naming
- Plugin name and skill name: kebab-case, `a-z 0-9 -`, no leading/trailing/double hyphens.
- Folder name == plugin `name`. Skill folder name == the skill's frontmatter `name` (validator error otherwise).
- Prefer specific, task-shaped names (`meeting-notes-summarizer`), not brand-only names.

## plugin.json (required fields)
```json
{
  "name": "<plugin-name>",
  "displayName": "<Human Name>",
  "version": "1.0.0",
  "description": "<1-2 sentences: what it does and for whom>",
  "author": { "name": "Naxasware", "url": "https://github.com/Naxasware" },
  "homepage": "https://github.com/Naxasware/Naxasware-Plugins/tree/main/plugins/<plugin-name>",
  "repository": "https://github.com/Naxasware/Naxasware-Plugins",
  "license": "Apache-2.0",
  "keywords": ["3-8 lowercase tags"],
  "metadata": { "category": "productivity" }
}
```
`sync_repo.py` forces `name` = folder name and `license` = Apache-2.0 and fills missing author/homepage/repository/displayName, so these never need manual fixing in the repo (still write them correctly). `metadata.category` is a free string (productivity, development, security, data, writing, research, general…). Do not add a `skills` key: `skills/` is scanned by default. Do not create `.claude-plugin/marketplace.json` inside a plugin.

## Versioning and changelog
- Semver `X.Y.Z`. Patch = fixes/wording. Minor = new backward-compatible capability. Major = changed output format, schema, or ID scheme.
- `CHANGELOG.md` uses Keep a Changelog. Each release: `## [X.Y.Z] - YYYY-MM-DD` with `### Added / Changed / Fixed`. The validator warns if the current version has no entry; the release notes are taken from that section.

## SKILL.md rules
- Frontmatter: `name` and `description` only (others are ignored by the validator but avoid clutter).
- `description`: 20–1024 chars (aim 300–800), states what it does AND when to trigger, includes realistic user phrasings, no `TODO`.
- Body under 500 lines. Detail goes to `references/`, linked by relative path like `references/details.md`. **Every `references/…`, `scripts/…`, `assets/…` path mentioned in SKILL.md must exist** (validator error).
- Scripts: `python3`, standard library only unless truly necessary; deterministic; exit non-zero on failure.

## Validator (what CI enforces)
Errors: invalid JSON; non-kebab name; non-semver version; missing README.md; missing/mismatched SKILL.md frontmatter; description length; missing referenced files; Python scripts that don't compile; secrets (GitHub/AWS/Anthropic/OpenAI/Slack keys, private key blocks) anywhere in text files.
Warnings: license not Apache-2.0 / text mentions the MIT license; CHANGELOG missing the current version; SKILL.md over 500 lines; short or TODO description; `ci-smoke.sh` not executable; plugin not yet in marketplace.json.

### Running it without the repo (Project sandbox)
```bash
mkdir -p /tmp/repo/plugins /tmp/repo/.claude-plugin
cp -R <built-plugin-folder> /tmp/repo/plugins/<plugin-name>
echo '{"name":"x","owner":{"name":"x"},"plugins":[]}' > /tmp/repo/.claude-plugin/marketplace.json
python3 05-validate_all_plugins.py /tmp/repo
```
Expect a "not listed in marketplace.json" warning (that's normal here) and `No errors.` Fix any error before delivering.

## What happens after the owner pushes
1. `ci.yml`: validates all plugins/skills, runs each `ci-smoke.sh`, regression-tests the scaffolder.
2. `sync.yml` (on push to `main` AND on same-repo PRs touching `plugins/**`): runs `scripts/sync_repo.py`, which regenerates `marketplace.json` and the README plugin table, normalizes each `plugin.json`, and commits the result to the branch. Fork PRs are skipped; the push to `main` after merge syncs them.
3. Release = push tag `<plugin-name>-v<version>`; `release.yml` checks it equals `plugin.json` version, then publishes the zip, `.skill` file(s), and `.full.md` (single-file instructions for non-Claude agents).

## Do not
- Edit `marketplace.json`, the README plugin table, or files outside `plugins/<name>/`.
- Add a per-plugin LICENSE (Apache-2.0 is inherited) unless asked. Never write "MIT" anywhere (the validator warns on it).
- Commit secrets, credentials, personal data, or generated artifacts (`dist/`, `*.pyc`, `*.skill`).
