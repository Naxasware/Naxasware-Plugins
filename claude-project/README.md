# Run this repo from a Claude Project

Goal: give Claude a Project that already knows this repo's structure, rules, and publishing flow. Then the only thing you do is paste a skill instruction document; Claude returns a validated plugin folder (as a zip) plus the exact git commands.

## Contents of this kit

| File | Where it goes |
|---|---|
| `PROJECT-INSTRUCTIONS.md` | Pasted into the Project's instructions |
| `knowledge/01-REPO-CONVENTIONS.md` … `04-WORKFLOW-CHEATSHEET.md` | Uploaded to project knowledge |
| `knowledge/05-validate_all_plugins.py` | Uploaded to project knowledge (auto-kept identical to `scripts/validate_all_plugins.py` by the sync workflow) |

## Step-by-step setup

1. **Turn on the capabilities Claude needs.** In Claude's Settings, enable **Code execution and file creation** (so Claude can run the validator and hand you a zip). Menu labels can differ slightly between web, desktop, and mobile.
2. **Create the project.** Open **Projects** in the left sidebar (or go to claude.ai/projects) and click **+ New Project**. Name it `Naxasware Plugin Builder`. The name and description are for you; Claude doesn't see them.
3. **Set the instructions.** In the project, click **Set project instructions**, paste the entire contents of `PROJECT-INSTRUCTIONS.md`, and click **Save instructions**.
4. **Add the knowledge.** In the project knowledge panel click **+** and upload the five files from `knowledge/`. Keep the filenames as they are; the instructions refer to them by name.
5. **Run a test.** Start a chat in the project and send:
   > Here is a skill instruction doc. Build the plugin. *(paste or attach any short playbook, e.g. "how we write release notes")*

   You should get: a one-line plan with names and assumptions, a zip of `plugins/<name>/`, validator output, and the commands to push.
6. **Publish** with the commands Claude gives you (they follow `04-WORKFLOW-CHEATSHEET.md`): unzip at the repo root, validate, commit, push. CI validates and the sync workflow updates `marketplace.json` and the README. Tag `<plugin>-vX.Y.Z` to release.

## Daily use

- **New skill:** open a new chat in the project, paste or attach the instruction doc. Nothing else.
- **Change to an existing skill:** paste the revised doc and say which plugin. Claude bumps the version, updates the CHANGELOG, and returns the whole folder.
- **Several skills at once:** one chat per plugin keeps things clean. Chats in a project don't share context, only the project knowledge does.

## Keeping the Project current

- If you change repo conventions (`docs/`, `scripts/`, workflows, template), update `knowledge/01…04` to match and re-upload. Delete the old versions first so stale rules don't linger.
- `05-validate_all_plugins.py` is regenerated by the sync workflow whenever `scripts/validate_all_plugins.py` changes. Re-upload it after such a change.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Claude pastes files as text instead of giving a zip | Code execution and file creation aren't enabled (step 1). The instructions make Claude fall back to labeled code blocks. |
| Claude says it validated but shows no output | Ask: "Run the validator and show me the raw output." The instructions forbid claiming checks that didn't run. |
| Claude edits `marketplace.json` or README | Remind it: "Deliver only `plugins/<name>/`." Then check that instruction 6 in the project instructions wasn't altered. |
| Generated skill ignores my document's details | Attach the document as a file instead of pasting a summary, and say what must be preserved verbatim. |
| Conventions changed but Claude uses old ones | Re-upload the updated knowledge files (see above). |
